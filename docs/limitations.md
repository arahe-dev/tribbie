# Limitations

- The latest spatial MoE scored 45/45 on the current procedural simulator manifest. Cases 1–40 were inspected during earlier variations; cases 41–45 are the newest prospective extension. Both the MoE and matched one-expert control scored 5/5 on cases 41–45, which is promising but not a broad generalization estimate.
- This is a Windows Isaac Sim fallback experiment, not Gazebo or ROS 2. The robot, physics, assets, and RTX camera rendering are simulator-specific.
- The scene is deliberately simple: one lit ground grid, one red pillar, one fixed camera configuration, and four coarse actions. It does not establish general navigation or transfer to a physical robot.
- Labels come from target pose via a transparent geometric supervisor. The policy gets pixels only, but the task and data distribution are controlled by that supervisor.
- The original balanced dataset has 520 images from 10 collection episodes. The newer rollout dataset adds 4,788 frames from 30 appearance groups, but it still uses one scene, one target, and a narrow set of start conditions; frame count should not be confused with environmental diversity.
- The initial held-out image benchmark has two test episodes (104 images), and the original demo comparison has five seeded trials per policy. Those older percentages have wide uncertainty and are not population estimates.
- The container-side transfer check gives the spatial MoE v3 0.769 accuracy / 0.760 macro F1 on a separately collected 104-image split, below its 0.988 / 0.943 rollout-held-out score. This is evidence of collection shift in the same scene/task; it is not an evaluation on new 3D environments.
- The original one-expert encoder slightly outperformed the four-expert model on its held-out images (0.883 vs. 0.872 macro F1). On the matched rollout data, the spatial one-expert ablation reached 23/25 versus 25/25 for the MoE and matched its 5/5 newest extension. The two-case difference is too small to establish that mixture routing helps; the one-expert forward pass is faster.
- STOP labels are defined at a 1.50 m supervisor boundary because the camera clips the target at shorter distances. Success is scored from 1.20–1.65 m and bearing <=0.18 rad. The claim is limited to this visible target size/range and rule.
- In the classical baselines, ResNet-18 is frozen ImageNet-1K V1, PCA is linear, and k-NN is supervised. The new MoE has a small action-supervised image encoder, but there is no learned dynamics model or reinforcement learning.
- Latency depends on GPU load, Windows scheduling, camera rendering, process IPC, and preprocessing. The latest model's A2000 forward p95 is 1.48 ms on a preloaded tensor; the full GPU request p95 was 5.04 ms while Isaac shared that GPU. CPU inference on the same workstation reached 1.98 ms request p95, but that is not A2000 inference. A cold GPU request reached about 167 ms. Nominal 6.67 Hz is the simulated decision interval, not a real-time throughput guarantee.
- Kit Python and CUDA PyTorch use separate processes because of a DLL conflict. Scripts assume Isaac Sim at `C:\isaacsim`; adjust the configured path elsewhere.
- The installed system has no standalone `nvcc`. Isaac's bundled Warp reports CUDA Toolkit 12.8; the project PyTorch wheel reports CUDA 13.0. The final operating-system query reported Windows 11 Pro build 26200 despite inconsistent early machine metadata.
